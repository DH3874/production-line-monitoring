## 장서진 사용자 앱 변경
- 공식 SendIssueMessageAsync(issueId, message)로 문의를 전송합니다. 기존 문제 안에 메시지를 저장하며 새 문제를 만들지 않습니다.
- GetIssueMessagesAsync(issueId, afterId)로 서버의 관리자·작업자 대화를 조회합니다. 화면에는 역할·이름·시간·내용을 표시합니다.
- 별도 5초 타이머로 선택한 문제의 새 메시지를 확인합니다. 문제별 메시지 캐시와 조회 번호를 관리하고 같은 번호는 중복 표시하지 않습니다.
- 전송 응답 번호와 조회 완료 번호를 분리해 조회와 전송이 겹쳐도 중간 답장을 건너뛰지 않습니다.
- 문제별 임시 입력을 유지합니다. 전송 중에는 중복 전송을 막고, 성공한 입력만 지웁니다. 실패 시 입력을 유지하며 자동 재전송하지 않습니다.
- 종결된 문제는 대화 조회만 가능합니다. 메시지는 공백 제거 후 1~2000자로 제한합니다.
- AI 상담은 별도 페이지·기존 호출을 유지합니다. AI 대화는 이 PC 저장이며 관리자 대화는 서버 DB 저장입니다.
- 확인→점검 시작→완료 요청, 관리자 반려 사유 표시, 로그인 만료 처리도 유지합니다.

## 서버/DB
- ASP.NET Core 서버와 EF Core SQLite가 연결됩니다. 실행 시 서버 ContentRoot/App_Data/productionline.db를 자동 생성하고 마이그레이션을 적용합니다.
- 사용자·권한·라인·검사·문제·상태 변경 이력·문의 메시지·통신 기록이 서버 DB에 저장됩니다.
- 기존 data/store.json 파일은 보존했습니다. 새 서버에는 이 JSON을 SQLite로 자동 이전하는 코드가 없습니다. 기존 데이터를 옮긴 것으로 간주하면 안 됩니다.
- 공용 클라이언트는 여전히 HTTP 오류 번호를 예외에 보존하지 않습니다. 앱은 서버 오류 문구를 보여주며 정확한 인증 만료 문구 `로그인이 필요합니다.`를 처리합니다.

## 연결 담당과 계약
- 서버·DB: 김하균, 사용자 앱: 장서진. 관리자 UI 답장 연결은 관리자 담당 영역입니다.
- 기본 같은 PC 주소: http://127.0.0.1:5050. 다른 PC는 PRODUCTIONLINE_SERVER_URL=http://실제서버PC-IP:5050 설정 후 앱 재실행. 실제 서버 PC IP는 미확정입니다.
- GET /api/issues/{id}/messages?afterId=마지막조회번호, POST 같은 주소 { message: 문자열 }.
- 응답 IssueMessageDto: Id(long), IssueId(Guid), SenderId, SenderName, SenderRole, Message, CreatedAt. 보낸 사람은 서버가 로그인 토큰으로 결정합니다.
- 401 재로그인, 403 권한 오류, 400 입력 오류, 404 문제 없음, 409 종결·상태 충돌은 서버가 반환합니다. 상태 변경/전송 오류에서는 입력을 유지하고 상태를 재조회하며 자동 재전송하지 않습니다.
