# 장서진 사용자 앱 복사본

## 최신 서버 파일 적용 (2026-10-19)

[서버파일_2026-10-19_적용완료.md](서버파일_2026-10-19_적용완료.md)가 아래 과거 기록보다 우선합니다. 전달받은 공용 파일 및 SQLite 서버를 적용했고, 사용자 앱의 관리자 메시지 전송·5초 증분 조회를 연결했습니다. 기존 관리자 채팅 미연결 설명은 과거 상태입니다.

이번 적용은 사용자가 전달한 서버·공용 파일 교체와 사용자 앱 복사본 수정에 한정합니다. 원본 사용자 앱, 관리자 앱, 영상·AI 소스는 유지합니다. 기존 솔루션에는 복사본을 추가하지 않았습니다.

## 실행

기존 서버를 먼저 실행하고 이 폴더의 실행.cmd를 실행합니다.
초기 사용자: worker1 / worker123!
다른 서버는 PRODUCTIONLINE_SERVER_URL 환경변수로 지정합니다.

## 사용자 UI 디자인 변경

- 장서진 사용자 앱 복사본만 변경. 관리자 앱·서버·공용 DTO/API는 유지.
- 남색 사이드 메뉴, 청록색 주요 버튼, 페이지 제목/설명, 하단 연결 상태, 흰색 패널로 구성.
- 검사 현황은 정상/불량/판정 불가/정상률 4개 카드. 라인 현황과 개별 기록은 구분 유지.
- 실시간 검사에는 카메라 미연결 안내를 표시하고 카메라 제어 영역을 분리. 기존 정상 기준 등록 기능의 버튼명을 '정상 기준 등록'으로 간소화.
- 문제 조치 단계·권한 안내와 AI/관리자 페이지 분리 및 기존 전송 흐름 유지.
- ModernUi.cs에 화면 레이아웃·스타일을 분리. UserMainForm.cs, CameraInspection.cs, 복사본 Form1.cs(로그인 색상/브랜드), Verification 코드 및 실행.cmd 수정.
- 최소 창 크기 1200×800, 기본 1400×900. 두 크기의 5개 페이지를 렌더링해 배치 검수. 기존 기능 자동 검증 통과. 물리 카메라의 수신 여부는 이전과 같이 이 장치에서 미검증.
- 실행.cmd는 artifacts-ui로 빌드하고 그 결과를 실행. 이전 bin이나 artifacts의 오래된 실행 파일과 구분됨. 해당 새 버전이 실행 중이면 종료 후 재실행.

## 페이지

SQLite 클래스 설계 적용 내용과 서버 담당 연결 사항은 [DB_연동안내.md](DB_연동안내.md)에 정리했습니다. Entity·DbContext는 서버 내부 모델이며 사용자 앱의 기존 공용 계약은 유지합니다.

1. 실시간 검사: 카메라 번호(기본 0)를 선택하고 카메라 연결을 누르면 PC에 연결된 웹캠 영상을 표시합니다. 정상 제품을 배치하고 '현재 영상을 정상 기준으로'를 누른 뒤 '검사 시작'을 누르면 1.5초 간격으로 프레임을 분석·전송합니다. '검사 중지'는 향후 검사를 멈추고 미리보기는 유지합니다. '연결 해제'는 검사를 중단하고 장치를 해제합니다. 기준은 메모리에만 보관되며 재연결·라인 변경 시 다시 등록해야 합니다.
2. 검사 개수·지난 기록: 서버 누적 수량, 정상률(정상 / 정상+불량), 최근 검사 기록을 표시합니다. 현재 서버 조회 제한 내 기록만 표시합니다.
3. 문제·조치: 유형·제목·증상을 등록하고 직접 입력한 처리 내용으로 확인/조치 중/완료 요청을 저장합니다. 확인→조치 중→완료 요청 순서를 UI에서 안내하며 완료 요청 후 편집을 막습니다. 등록자·등록/갱신 시각·문제 번호·마지막 메모를 표시하고, 전체 처리 이력이 아님을 구분합니다. 새로 입력한 조치만 전송합니다. 서버는 최신 메모 갱신과 과거 이력 보존을 담당해야 합니다. 현재 제공된 JSON 서버는 최신 메모만 교체하므로 별도의 과거 조치 이력을 보존하지 않습니다. 종결은 관리자 역할입니다.
4. AI 상담: 문제별 질문·답변·근거를 누적 표시합니다. AI 응답은 기존 상담 API를 사용합니다.
5. 관리자 상담: 문제별 메시지를 기존 문제 등록 API로 관리자 목록에 전달합니다. 원래 문제 ID를 본문에 포함합니다. 관리자 답장 API가 없으므로 양방향 실시간 채팅은 지원하지 않으며 화면에 명시합니다.

대화는 %LOCALAPPDATA%/ProductionLine.UserApp.Moon 아래 사용자별 JSON에 보존됩니다. 다른 PC나 계정과 공유되지 않습니다. 같은 PC의 해당 Windows 사용자가 접근 가능한 로컬 기록입니다.

## 팀 연동이 남은 부분

- 영상처리 담당: 현재 기존 OpenCvSharpFrameAnalyzer 예제를 그대로 호출합니다. 실제 제품 ROI·조명·임계값·제품 감지 조건은 현장에 맞춰 검증이 필요합니다. 검사 시각은 서버 처리 시각이며 촬영 프레임 식별자·이미지 저장 계약은 별도 필요합니다.
- 김하균·조영준: 관리자 메시지 수신·답장 API와 저장 계약. 현재 문의 등록은 채팅 수신의 대체 구현이 아닌 기존 문의 기능입니다.
- 공도현·김하균: 필요 시 서버에 문제별 대화 이력을 보관하고 조회하는 API. 현재 AI에는 매번 현재 질문과 문제 ID만 전달합니다.

## 2026-10-16 수정·검증 및 연결 안내

- 수정 범위: 이 복사본의 UserMainForm.cs, Verification 검사 프로그램, 이 문서. 기존 공용·서버·관리자 소스 유지.
- 담당 연결: 김하균 서버 담당. 서버 주소는 PRODUCTIONLINE_SERVER_URL, 포트 5050 유지. 미설정 시 기존 클라이언트 기본값인 127.0.0.1:5050 사용. 실제 서버 PC 주소는 미확정.
- 호출 계약 유지: UpdateIssueAsync(문제 ID, UpdateIssueStatusRequest(상태, 새 조치 내용)). 이전 메모를 합치지 않음. 응답은 IssueDto. 수행자와 변경 시각·이력은 서버에서 관리.
- UI 처리: 저장 성공 후 입력 초기화 및 목록 갱신. 조치·상담 전송 실패 시 오류를 상단에 표시하고 입력 보존. 다시 버튼을 눌러 재시도 가능.
- 자동 검증: 별도 로컬 테스트 서버에서 문제 등록 값, 새 조치만 전송, 완료 요청 상태, 서버 오류 시 조치 보존·재시도, AI 답변·근거, AI 전송 실패·재시도, 관리자 문의, 로컬 대화 복원, 연결 단절 시 질문 보존 등 13개 검증 통과. 테스트 계정 기록은 검증 후 삭제. 운영 서버 저장 데이터에는 테스트 자료를 넣지 않음.
- 검증 한계: 테스트 서버 응답을 이용한 사용자 앱 검증이며 실제 AI 품질, 관리자 수신 화면, DB 저장·상태 변경 이력은 검증 범위가 아님. 기존 문제 등록 다이얼로그의 수동 입력부터 DB까지의 전체 검증은 별도 필요.

## 카메라 연결·검사 시작 추가

- 사용 순서: 서버 실행 → 사용자 로그인 → 실제 라인 선택 → 카메라 번호 0 선택 → 카메라 연결 → 정상 제품 배치 → 현재 영상을 정상 기준으로 → 검사 시작. 여러 웹캠은 번호를 바꿔 연결합니다. 장치가 없거나 권한이 차단되면 영상 영역 아래 안내가 표시됩니다.
- 장치 범위: 로컬 PC에서 DirectShow로 열 수 있는 웹캠/USB 카메라. IP 카메라 URL이나 별도 산업용 SDK 장치는 이번 변경에 포함하지 않습니다.
- 주기: 영상 읽기는 백그라운드, UI 갱신 약 50ms, 검사 1.5초 간격이며 분석·전송이 겹치지 않습니다. 새 프레임이 없거나 3초 이상 오래되면 저장하지 않고 중지합니다.
- 개수 의미: 1회 성공적으로 저장한 검사 프레임당 1건입니다. 동일 제품을 계속 비추면 반복 검사되므로 제품 통과 감지에 따른 생산 수량 집계는 별도입니다.
- 서버 담당 연결: 기존 SimulateInspectionAsync(InspectionRequest(LineId, ShapeScore, ColorScore, ImageAcquired)) → POST /api/inspections/simulate를 그대로 사용합니다. API 이름은 simulate이지만 점수는 현재 카메라 프레임과 정상 기준을 분석해 계산합니다. 응답 InspectionDto를 표시하고 기존 조회로 개수·기록을 갱신합니다. 기준 임계값은 기존 서버 VisionInspector의 형태 0.85, 색상 0.80 기본값입니다. 주소는 PRODUCTIONLINE_SERVER_URL, 포트 5050 유지.
- 분석/서버 통신 실패 시 검사 중지, 자동 재전송 없음. 중지 전 이미 전송한 1건은 서버에서 저장될 수 있습니다. 원본 이미지·촬영 시각·기준 이미지는 서버에 보내지 않습니다.
- 변경 파일: UserMainForm.cs, CameraInspection.cs, CameraSession.cs, AssemblyInfo.cs, 사용자 앱 csproj, Verification 코드, 이 문서. 공용 클라이언트·DTO·서버·원본 영상처리 소스는 유지.
- 검증: 합성 이미지 정상/불량 분석, 준비 전 검사 차단, 합성 프레임으로 검사 시작→기존 계약 전송, 중지 후 추가 전송 없음, 서버 오류 시 중지 검증 통과. 기존 조치·상담 회귀 검증 통과. 물리 카메라는 이 PC에서 열리지 않아 실제 수신·현장 판정 정확도는 미검증.
