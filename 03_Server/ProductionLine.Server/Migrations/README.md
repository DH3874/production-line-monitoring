# Migrations 폴더 — DB 공사 계획서

## 이 폴더는 뭐예요?

DB의 표를 만들거나 바꾸는 **공사 계획서(마이그레이션)**가 들어 있어요.
`Data` 폴더의 표 클래스를 바꾸면, 그 변화를 DB에 반영하기 위한 계획서를 여기에 하나씩 추가해요.

- 계획서는 **번호(날짜·시각) 순서대로** 적용돼요.
- 서버가 켜질 때 `DatabaseInitializer`가 **아직 적용 안 된 계획서만 자동으로** 적용해요.
- DB 안의 `__EFMigrationsHistory` 표가 "몇 번까지 적용했는지"를 기억해서 같은 공사를 두 번 하지 않아요. 그래서 기존 데이터는 그대로 남아요.

## 지금 있는 계획서 3개

| 순서 | 계획서 | 무엇을 바꾸나 |
|---|---|---|
| 1 | `20261016070834_InitialCreate` | 처음 표 만들기: `Users`, `UserLineAccesses`, `Lines`, `Inspections`, `Issues`, `IssueHistories` |
| 2 | `20261017060541_AddIssueMessages` | 문의 메시지 표 `IssueMessages` 추가 (작업자 문의 ↔ 관리자 답변) |
| 3 | `20261018150401_AddRequestLogs` | 통신 기록 표 `RequestLogs` 추가 (7일 보관, 지난 기록은 CSV 백업) |

세 계획서 모두 **표를 새로 만들기만** 하고, 기존 표나 데이터를 지우지 않아요.

## 파일 종류

계획서 하나에 파일이 2개씩 있고, 폴더 전체에 요약 파일이 1개 있어요.

| 파일 | 하는 일 | 손으로 고쳐도 되나 |
|---|---|---|
| `날짜_이름.cs` | 실제 공사 내용. `Up` = 적용할 때, `Down` = 되돌릴 때 | 적용된 뒤에는 고치지 않기 |
| `날짜_이름.Designer.cs` | 그 계획서를 만든 시점의 표 모양 기록 | 고치지 않기 (도구 전용) |
| `AppDbContextModelSnapshot.cs` | **지금** 표 모양 전체 요약. 새 계획서를 만들 때 비교 기준 | 고치지 않기 (새 계획서를 만들 때마다 도구가 다시 씀) |

그래서 이 폴더의 `.cs` 파일에는 주석을 달지 않았어요. 설명은 이 README에만 적어요.

## 새 계획서를 만들 때 (표 모양을 바꿨을 때)

1. `Data` 폴더의 표 클래스나 `AppDbContext.cs`를 고쳐요.
2. Visual Studio에서 **도구 → NuGet 패키지 관리자 → 패키지 관리자 콘솔**을 열어요.
3. 기본 프로젝트를 `ProductionLine.Server`로 고르고 입력해요.
   ```powershell
   Add-Migration 바뀐내용을_영어로
   ```
   예: `Add-Migration AddAiConsultLogs`
4. 이 폴더에 새 파일이 생겼는지, `Up` 안에 **의도한 변경만** 있는지 확인해요. 특히 `DropTable`, `DropColumn`(지우기)이 있으면 데이터가 사라질 수 있으니 꼭 확인해요.
5. 서버를 켜면 자동으로 적용돼요.

## 지켜야 할 약속

- **계획서는 서버 담당(김하균)만 만들어요.** 두 사람이 따로 만들면 순서와 요약 파일이 꼬여서 서버가 안 켜질 수 있어요.
- **이미 적용된 계획서는 지우거나 고치지 않아요.** 바꾸고 싶으면 새 계획서를 하나 더 만들어요.
- 조원에게 서버를 보낼 때는 이 폴더를 **통째로** 같이 보내요. 파일이 빠지면 DB가 다르게 만들어져요.

## DB를 처음부터 다시 만들고 싶을 때

서버를 끄고 `App_Data/productionline.db` 파일만 지운 뒤 서버를 켜면, 계획서 3개가 순서대로 다시 적용되고 시연용 기본 데이터가 들어가요.
`App_Data` 폴더를 통째로 지우면 통신 기록 CSV 백업도 같이 지워지니 주의해요.
