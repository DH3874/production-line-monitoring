# 서버에 추가한 기능 한눈에 보기 (2026-10-19)

처음 받은 기본 서버에서 **무엇이 바뀌었고, 각 기능이 무슨 일을 하는지** 쉽게 정리했습니다.
코드 위치는 모두 `with claude` 폴더 기준입니다.

> **10-19 업데이트:** 공도현 님의 **단체 채팅(8번)**과 **외부 AI 연결(9번)**을 합쳤습니다. API 목록, 번호표, 설정, 파일 위치, 확인 상태도 함께 고쳤습니다.

## 0. 서버 구조 한 장 요약

```
관리자 앱 ─┐
          ├─→  서버(API 창구)  →  DB(SQLite 파일)
사용자 앱 ─┘        │
                   ├─ 로그인·권한 확인
                   ├─ 검사·문제·메시지 저장
                   ├─ 통신 기록 남기기
                   ├─ 단체 채팅 → data/group-chat.json (JSON 파일)
                   └─ AI 상담 → 외부 AI(Gemini/OpenAI), 안 되면 매뉴얼
```

- 앱은 DB를 직접 만지지 않고, **서버 창구(API)에 부탁**합니다.
- 서버는 **누구인지, 권한이 있는지** 확인한 뒤 DB에 저장하거나 꺼내 줍니다.
- 비유: 앱 = 손님, 서버 = 창구 직원, DB = 금고

## 1. 저장 방식: JSON 파일 → SQLite DB

| | 전 | 지금 |
|---|---|---|
| 저장 위치 | `data/store.json` (메모장 같은 파일) | `App_Data/productionline.db` (DB 파일) |
| 장점 | 단순함 | 기록이 많아도 빠르고, 표끼리 연결되고, 동시에 써도 안전 |

- 앱이 부르는 함수와 주소는 **그대로**라서 앱 코드는 안 바뀌었습니다.
- 처음 켤 때 **시연용 기본 데이터**가 자동으로 들어갑니다: 관리자 `admin`, 작업자 `worker1`, 라인 4개(LINE 1 실제, 2~4 가상).
- 기존 `store.json`의 테스트 기록은 옮기지 않았습니다.
- 예외: **단체 채팅만** DB가 아니라 JSON 파일(`data/group-chat.json`)에 저장합니다(아래 8번, 팀이 그렇게 정함).

## 2. DB 표 8개

| 표 | 저장하는 것 |
|---|---|
| 사용자 (`Users`) | 아이디, 이름, 관리자/작업자, 비밀번호(암호화), 사용 가능 여부 |
| 허용 라인 (`UserLineAccesses`) | 누가 어느 라인을 볼 수 있는지 |
| 라인 (`Lines`) | 라인 상태, 정상·불량·판정 불가 누적 개수 |
| 검사 결과 (`Inspections`) | 검사 한 건마다 결과, 점수, 이유, 시각 |
| 문제 (`Issues`) | 문제 내용과 **지금 상태** |
| 상태 변경 이력 (`IssueHistories`) | 누가 언제 상태를 **무엇에서 무엇으로** 바꿨는지 |
| 문의 메시지 (`IssueMessages`) | 문제에 대한 작업자 문의, 관리자 답변 |
| 통신 기록 (`RequestLogs`) | 앱과 서버가 주고받은 요청 기록 (아래 7번) |

- 표마다 클래스가 하나씩 있고(`Data` 폴더), 표를 묶어 주는 `AppDbContext`까지 클래스는 9개입니다.
- 표를 만들거나 바꾸는 설계도를 **마이그레이션**이라고 합니다. 지금 3개(`InitialCreate`, `AddIssueMessages`, `AddRequestLogs`)입니다.

## 3. 서버가 켜질 때 DB 자동 준비

- DB 파일이 없으면 **표를 새로 만들고** 기본 데이터를 넣습니다.
- 새 마이그레이션이 있으면 **자동으로 적용**합니다. 이미 있는 데이터는 지우지 않습니다.
- 그래서 조원 PC에서 처음 켜도 바로 동작합니다. DB 파일을 보낼 필요가 없습니다.

## 4. 로그인과 권한

- **로그인:** 아이디·비밀번호가 맞으면 "출입증(토큰)"을 줍니다. 앱은 이후 요청마다 이 출입증을 보여 줍니다.
- **매 요청마다 DB에서 다시 확인:** 계정을 비활성화하거나 라인 권한을 바꾸면 **다음 요청부터 바로** 적용됩니다.
- **출입증은 서버 메모리에만** 있습니다. 서버를 다시 켜면 모두 다시 로그인해야 합니다. 유효 시간은 8시간입니다.
- 작업자는 **자기 라인**만 보고, 관리자 기능은 쓸 수 없습니다.
- 회원가입은 없습니다. **관리자가 작업자 계정을 만들어 줍니다.**

## 5. 문제 처리 순서 (안 A)

```
작업자:  발생 → 확인 → 조치 중 → 완료 요청
관리자:  완료 요청 → 종결
         완료 요청 → 조치 중 (반려, 사유 필수)
```

- 순서를 건너뛰거나, 같은 상태를 다시 보내거나, 종결 뒤에 바꾸려고 하면 서버가 거절합니다(409).
- 상태가 바뀔 때마다 **변경 이력**이 저장됩니다. 거절된 요청은 이력에 남지 않습니다.
- 사용자 앱에 **"확인" 버튼**이 있어야 이 순서대로 쓸 수 있습니다(장서진 님에게 요청함).

## 6. 문의 메시지 (작업자 ↔ 관리자)

- **보내기:** 선택한 문제에 메시지를 남깁니다. 1~2,000자, 앞뒤 공백은 지웁니다.
- **읽기:** 그 문제의 메시지를 보낸 순서대로 줍니다. "이 번호 다음 것만" 받을 수도 있습니다.
- 앱은 **5초마다** 새 메시지만 물어봅니다. 서버가 먼저 알려 주는 방식은 아닙니다.
- 자기 라인의 문제에만 보낼 수 있고, **종결된 문제는 읽기만** 됩니다.
- AI 상담과는 **별개**인, 사람끼리의 대화입니다.

## 7. 통신 기록 (나중에 "보냈다/못 받았다" 확인용)

**남기는 것**
- 저장·변경 요청 전부 (문제 등록, 상태 변경, 메시지 보내기 등)
- 실패한 요청 전부 (권한 없음, 로그인 실패 등)
- 새 메시지를 **응답으로 보낸** 조회 ("메시지 12번 조회 응답")

**남기지 않는 것**
- 비밀번호, 출입증(토큰), 메시지 내용
- 성공한 일반 조회, 새 메시지가 없었던 5초 확인

**자동 정리**
- 최근 **7일**은 항상 보관합니다.
- 서버가 매일 한 번, 7일 지난 기록을 `App_Data/통신기록_백업/`에 **CSV 파일로 먼저 저장**하고 지웁니다. 엑셀로 열 수 있습니다.
- 파일 저장에 실패하면 지우지 않고 다음 날 다시 합니다.
- 보관 기간은 `appsettings.json`의 `"RequestLogRetentionDays": 7`에서 숫자만 바꾸면 됩니다.

**알아 둘 점**
- 이 기록은 **서버에 도착한 요청**만 증명합니다. 작업자 PC에서 보냈는데 서버까지 못 온 경우는 앱 쪽 기록이 필요합니다.
- "조회 응답"은 서버가 보냈다는 뜻이고, 앱 화면에 실제로 떴는지까지는 증명하지 않습니다.

## 8. 단체 채팅 (관리자 + 모든 작업자) — 새로 추가

공도현 님이 만든 것을 서버에 합쳤습니다. 카톡 단체방처럼 **문제와 상관없이 모두에게 알리는 곳**입니다.

| | 문의 메시지 (6번) | 단체 채팅 |
|---|---|---|
| 누구와 | 작업자 1명 ↔ 관리자 | 관리자 + 모든 작업자 |
| 무엇에 대해 | 특정 문제 하나 | 아무 내용 (공지, 상황 공유) |
| 저장 | DB `IssueMessages` 표 | `data/group-chat.json` 파일 |

- **자동 참여:** 관리자가 아이디를 만들면 그 사람은 **바로** 단체방에 들어옵니다. 따로 초대할 필요가 없습니다.
- **비활성화하면 바로 차단:** 사용 중지된 계정은 읽기·보내기 모두 막힙니다.
- **저장:** 최근 **5,000건**까지 JSON 파일에 보관하고, 오래된 것부터 지웁니다.
- **중복 방지:** 메시지마다 앱이 만든 고유 번호가 붙어서, 같은 메시지를 다시 보내도 한 번만 저장됩니다.
- **동시 전송:** 여러 명이 동시에 보내도 번호가 겹치지 않습니다. 윈도우가 파일을 잠깐 붙잡아 저장이 거절되면 **잠깐 기다렸다 다시 저장**합니다(김하균 추가).
- **앱:** 2초마다 새 메시지를 확인하고, 안 읽은 수를 표시합니다.
  - 관리자 앱: 위쪽 **"단체 채팅" 버튼** → "단체 채팅 (1)"
  - 작업자 앱: 왼쪽 메뉴 **"06 단체 채팅"** → "06 단체 채팅 (1)"
- 1~2,000자, 빈 메시지는 거절(400). 저장 실패 시 503.

## 9. AI 상담 — 외부 AI 연결 (새로 추가)

공도현 님이 만든 것을 서버에 합쳤습니다.

- **순서:** 질문이 오면 **외부 AI(기본 Gemini, OpenAI로 바꿀 수 있음)**에 물어봅니다.
- **안 될 때:** 키가 없거나, 연결이 안 되거나, 사용 한도를 넘으면 **매뉴얼(JSON) 답변으로 대신**합니다. 그래서 키가 없어도 상담은 됩니다.
- **대기 시간:** Gemini는 최대 30초. 그래서 작업자 앱은 이 요청만 **35초**까지 기다립니다(다른 요청은 10초).
- **사용 한도:** 1분에 20번, 하루 100번 (`appsettings.json`에서 변경).
- **상담 기록은 저장하지 않습니다**(팀 결정). 서버에도, 작업자 PC에도 남지 않습니다. 앱을 닫으면 대화가 사라집니다.
  - 대신 `data/ai-events.jsonl`에 "AI 성공", "매뉴얼로 대체" 같은 **진단 코드만** 남습니다. 질문·답변 내용은 없습니다.

**API 키 넣는 법 (서버 PC에서만)**
- 키는 **서버에만** 둡니다. 앱·GitHub에 넣지 않습니다.
- `scripts/set-gemini-key.cmd` 실행 → 키 입력 → 이 PC에 암호화해서 저장(윈도우 DPAPI, 이 PC·이 계정에서만 풀림)
- 또는 환경변수 `GEMINI_API_KEY`에 넣고 서버 실행 (환경변수가 우선)
- 서버 켜기: `scripts/run-server-gemini.cmd` (Gemini) / `scripts/run-server-ai.cmd`

## 11. 서버 대답 번호표

| 번호 | 뜻 | 앱에서 할 일 |
|---|---|---|
| 200 | 성공 | 화면 갱신 |
| 400 | 보낸 내용이 잘못됨 (빈 값, 너무 김, 없는 라인) | 메시지 보여 주기 |
| 401 | 로그인 필요 (만료, 비활성화, 서버 재시작) | 로그인 화면으로 |
| 403 | 권한 없음 | 메시지 보여 주기 |
| 404 | 없음 (없는 문제 번호) | 목록 새로고침 |
| 409 | 지금 상태와 안 맞음 (순서, 중복, 종결됨) | 메시지 보여 주고 다시 조회 |
| 500 | 서버 안에서 고장 | 서버 담당에게 알리기 |
| 503 | 단체 채팅 저장 실패 | 같은 내용으로 다시 보내기 (중복 저장 안 됨) |

쉽게 기억하기: **200번대 = 잘됨, 400번대 = 보낸 쪽 문제, 500번대 = 서버 문제**

## 12. 설정 파일 (`appsettings.json`)

데이터가 아니라 **서버의 메모지**입니다. 숫자만 바꾸고 서버를 다시 켜면 반영됩니다.

| 항목 | 뜻 |
|---|---|
| `ServerUrl` | 서버가 요청을 받는 주소와 포트 (`0.0.0.0:5050` = 이 PC의 모든 주소, 5050번) |
| `RequestLogRetentionDays` | 통신 기록 보관 기간 (7일) |
| `Ai:Provider` | 쓸 AI (`Gemini` 또는 `OpenAi`) |
| `Gemini` / `OpenAi` | 모델 이름, 대기 시간, 답변 길이, 1분·하루 사용 한도, 켜기/끄기(`Enabled`) |
| `Gemini:UseSavedKey` | `set-gemini-key.cmd`로 저장한 키를 쓸지 (`true`) |

API 키는 이 파일에 **넣지 않습니다**(GitHub에 올라가기 때문).
