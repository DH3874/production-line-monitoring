## 왜 바꿨나
- YOLO가 휴대폰 기종을 알아내서 화면에는 보여 줬지만 DB에는 저장하지 않았습니다. 이제는 "어떤 기종에서 불량이 많았나"를 볼 수 있습니다.
- 같은 검사 결과가 서버에 두 번 오더라도 기록은 한 건만 남게 했습니다. 예를 들어 네트워크가 끊겨서 다시 보내는 경우입니다.

## 요청 번호로 중복 막기 — 한눈에 보기

**문제 상황:** 휴대폰 1대를 검사했는데 네트워크가 잠깐 끊긴 경우

```
[작업자 앱] ──검사 결과──▶ [서버] 저장 완료 ✅
[작업자 앱] ◀──응답── ✖ (네트워크 끊겨서 응답을 못 받음)
[작업자 앱] "실패했나?" → 같은 결과를 다시 보냄
```

| | 요청 번호 없을 때 (예전) | 요청 번호 있을 때 (지금) |
|---|---|---|
| 1번째 전송 | 저장 (정상 1개) | 번호 `A123`으로 저장 (정상 1개) |
| 2번째 전송 (같은 휴대폰) | **또 저장** → 정상 2개 ❌ | 번호 `A123`이 이미 있음 → **저장 안 함**, 처음 기록을 돌려줌 → 정상 1개 ✅ |

**정리:** 앱이 휴대폰 1대마다 고유 번호(요청 번호)를 붙여 보냅니다. 서버는 이미 받은 번호면 다시 저장하지 않습니다. 택배 송장 번호처럼, 같은 번호의 택배는 두 번 접수하지 않는 것과 같습니다.

- 휴대폰이 바뀌면 번호도 새로 만들어지므로 다른 휴대폰은 정상적으로 각각 저장됩니다.
- 지금 앱은 실패해도 자동으로 다시 보내지 않습니다. 그래서 이 기능은 **나중에 "다시 보내기"를 넣어도 안전하게** 해 두는 장치입니다.

## 저장 사진은 그대로 (결정)
- 휴대폰 1대에 기록은 1건만 남깁니다. 이 동작은 원래부터 그랬습니다.
- 저장하는 사진은 **처음으로 휴대폰 전체가 화면에 들어와 인식된 순간**의 사진입니다. 검출 결과가 나오고 벨트 가속과 분류가 시작되는 바로 그때입니다.
- 마지막 사진이나 중앙 사진으로 바꾸지 않고, 지금 방식을 그대로 두기로 했습니다.

## 같은 날 함께 바뀐 DB
- `Inspections` 표에서 안 쓰던 `ShapeScore`·`ColorScore` 칸을 지웠습니다(`20261022130000_RemoveInspectionScores`). 기존 검사 기록은 그대로 남습니다.
- 센서·벨트 기록 표 `LineHardwareLogs`를 추가했습니다(`20261022120000_AddLineHardwareLogs`). 10초에 1번, 그리고 상태가 바뀐 순간에 저장하고, 7일이 지난 기록은 지웁니다.

서버를 처음 켤 때 위 변경이 DB에 자동으로 적용됩니다. 기존 데이터는 지워지지 않습니다.
