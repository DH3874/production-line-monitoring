# 보고서 정리 (report_from)

김하균 정리 (2026-10-23 최종). 생산 검사 보고서를 어떻게 만들었는지와 예시 파일입니다.
**보고서 기능은 final 폴더에 만들어져 있습니다** (서버 `LineReportService.cs`, 관리자 앱 `AdminMainForm.cs`).

## 파일

| 파일 | 내용 |
|---|---|
| `보고서_예시.csv` | 실제 보고서 기능으로 뽑은 예시 (가짜 데이터 09:00~11:00). 엑셀로 열면 됨 (UTF-8 BOM) |
| `보고서_예시_미리보기.png` | 위 CSV를 엑셀로 열었을 때 모습 (검사 이력은 8줄만 표시) |

## 쓰는 방법 (관리자 앱만)

- **기간:** 관리자 앱에 로그인한 시각 ~ 앱을 끄는 시각
- **앱을 끄면 자동 저장**, 중간에는 **[보고서 저장]** 버튼
- 저장 위치: `문서\생산라인 보고서\1번라인_생산검사보고서_시작-끝.csv`
- 서버 창구: `GET /api/reports/lines/1?from=…&to=…` (관리자만, CSV 글자를 돌려줌)

## 정한 것

1. **제목:** `1번 라인 - 생산 검사 보고서`
2. **형식:** CSV, 그래프 없이 표만
3. **맨 위:** 검사 기간, 작성자, 작성 시각
4. **실시간:** 보고서를 만드는 그 순간까지의 최신 DB 데이터
5. **기종 미확인(판정 불가)은 기종별 분석에서 뺌**
6. **긴급 정지 버튼은 이벤트 기록**에 넣음
7. **센서는 5분 단위 표** (평균·최고 온도, 습도, 가스). 벨트 보드가 연결된 시간만
8. 센서 기록 보관은 7일 (7일보다 긴 기간이면 센서 칸이 비게 됨)

## 보고서 칸과 DB 위치

| 칸 | 내용 | DB 표 |
|---|---|---|
| 1. 검사 요약 | 총 검사, 정상, 불량, 판정 불가, 불량률 | `Inspections` |
| 2. 기종별 분석 | 기종(YOLO 클래스 이름 그대로), 검사, 정상, 불량 | `Inspections.PhoneModel` |
| 3. 센서 기록 | 5분 단위 평균·최고 온도, 습도, 가스(MQ-9 A0) | `LineHardwareLogs` (10초마다, 7일 보관) |
| 4. 문제·조치 | 등록 시각, 문제, 상태, 종결 시각 | `Issues`, `IssueHistories` |
| 5. 검사 이력 | 검사 시각, 판정, 기종, 신뢰도 (기간 안 전부) | `Inspections` |
| 6. 이벤트 기록 | 벨트 구동·정지, 긴급 정지 작동·해제, 보드 연결, 문제 등록·상태 변경 | `LineHardwareLogs`, `Issues`, `IssueHistories` |

불량률 = 불량 ÷ (정상 + 불량) × 100 (판정 불가는 빼고 계산, 관리자 앱과 같은 기준)
