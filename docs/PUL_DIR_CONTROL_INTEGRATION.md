# 선택한 컨베이어 제어 방식 통합

이 문서는 최초 통합 기록입니다. 이후 이동 중 구동 제한을 수정하고 자동 재구동·낮은 속도 출발을 반영했습니다. 최신 사용법은 [자동 검사 흐름](AUTO_INSPECTION_FLOW.md)을 따릅니다.

입력 폴더: `C:/Users/moble/OneDrive/Desktop/컨베이어 제어`

원본은 읽기만 했으며 현재 `2차 프로젝트 생산라인` 솔루션에 제어 기능을 가져왔습니다. 원본 폴더의 예전 모델·서버·관리자·AI 구현은 덮어쓰지 않았습니다.

## 변경

- Arduino: PUL 2번, DIR 3번 LOW, 반주기 지연 10µs, V2 식별, 3초 통신 중단 정지. 구동 명령 전까지 정지합니다.
- C# 통신: V2 펌웨어만 연결하며 예전 PWM 펌웨어와 혼용하지 않습니다.
- 아두이노 설정·업로드 창, CLI 도구·라이선스·출처 정보, 실행 스크립트를 추가했습니다. 설정·업로드 버튼의 동작은 전달받은 구현을 바탕으로 합니다.
- 검출 후 STOP 응답 → 정지 대기 → 새 프레임 검사 → 저장 → 완료·해제 → 수동 구동 흐름을 연결했습니다.
- 검사·저장·응답 실패 시 정지 보류와 수동 재시도, 완료 제품이 빠져나갈 때까지 중복 정지 방지를 반영했습니다.
- 최근 모델 3종 선택, 6클래스 기본 모델, 50% 신뢰도 기준, 품질 판정 미지원과 검출 신뢰도 저장은 유지했습니다. 새 기종도 정지 대상입니다.
- 작은 창에서 버튼이 가려지지 않도록 카메라·모델/업로드·벨트·검사 완료 조작을 네 줄로 구성했습니다.

## 실행

기존 서버 실행 → 최상위 `컨베이어_통합실행.cmd` 실행 → 사용자 로그인 → 아두이노 설정·업로드 → Mega COM 선택 → 업로드·연결 → 카메라 연결 → 검사 시작 → 벨트 구동.

업로드·연결은 실제 보드의 코드를 교체합니다. 이번 통합 작업에서는 실행하지 않았습니다. Arduino IDE로 직접 업로드할 때는 현재 솔루션의 `hardware/ConveyorYoloControl/ConveyorYoloControl.ino`를 사용합니다.

## 검증

| 검증 | 결과 |
|---|---|
| 사용자 앱·검증 프로젝트 빌드 | 경고 0, 오류 0 |
| 실제 펌웨어 소스 PC 모의 실행 | 15개 통과 |
| 업로드 도구·실패·취소·포트 처리 | 16개 통과, 업로드는 모의 실행 |
| 아두이노 설정 창 | 12개 통과 |
| 실제 ONNX + 모의 카메라·벨트·서버 | 38개 통과 |

총 81개를 통과했습니다. 실제 AVR 재컴파일·보드 업로드·물리적 모터 구동은 수행하지 않았습니다. 모터 과열의 해소 여부도 확인하지 않았습니다. 코드의 정지 응답은 PUL 펄스 생성 중단이며 모터 전원 차단이나 실제 속도 측정을 뜻하지 않습니다.

전체 솔루션 빌드는 실행 중인 서버의 DLL 복사 잠금 때문에 서버 출력 단계에서 실패했습니다. 사용자 앱은 정상 빌드됐고 서버 소스·API는 변경하지 않았습니다. 전체 빌드는 서버 종료 후 다시 실행하면 됩니다.
