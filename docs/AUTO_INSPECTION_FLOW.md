# 선택 기능: 이동하면서 검출하고 정지 후 자동 재구동

> 이 문서는 기존 선택 정지 모드 안내입니다. 현재 기본은 **인식돼도 멈추지 않는 연속 검출**이며 정지 체크는 해제되어 있습니다. [현재 기획·기능 정리](PROJECT_OVERVIEW_CURRENT.md)를 우선 참고하세요. 아래 체크 설정을 직접 켠 경우에만 정지 흐름이 적용됩니다.

이 선택 모드의 흐름은 **이동하며 카메라 검출 → 휴대폰 인식 → 정지 → 새 영상 검사·저장 → 자동 이동**입니다. 이전 수동 해제 중심의 동작을 수정했습니다.

## 적용 및 사용

1. 기존 사용자 앱을 닫고 최상위 `컨베이어_통합실행.cmd`를 다시 엽니다. 서버는 켜둡니다. 실행 중이던 창에는 코드 수정이 자동 적용되지 않습니다.
2. 사용자 로그인 → **아두이노 설정·업로드 → COM3(실제 Mega 포트) → 업로드·연결**. 수정한 출발 펄스 설정을 보드에 다시 올리는 단계입니다.
3. **휴대폰 검출 시 정지**, **검사 후 자동 재구동** 두 항목을 체크합니다.
4. **카메라 연결 → 검사 시작 → 벨트 구동**. 처음 벨트 출발은 사용자가 요청합니다. 영상 분석은 이동 중에도 계속하며 구동 버튼을 막지 않습니다.
5. 휴대폰이 검출되면 정지 응답을 확인하고 기본 500ms 대기 후 새 영상으로 검사·저장합니다. 그 작업이 성공하면 자동으로 다시 이동합니다. 정지 시간에는 대기 외에 촬영·분석·저장 시간이 추가됩니다.
6. 같은 제품이 빠져나갈 때까지 다시 멈추거나 저장하지 않습니다. 다음 제품과 사이에 빈 구간이 있어야 합니다.

시작 전 벨트가 연결된 정지 상태이면 카메라 검출 화면만 보여주고 제품 기록을 미리 저장하지 않습니다. 물체 도착은 이동 중 검출을 기준으로 처리합니다.

## 검출 조건

현재 기본 모델은 신뢰도 50% 이상인 휴대폰 클래스를 사용합니다. 제공된 기종 라벨은 후면 카메라 부근을 둘러싼 박스이므로 해당 부분이 카메라에 보이고 학습 사진과 비슷한 방향·조명에서 인식되는지 확인해야 합니다. 박스가 전혀 나오지 않으면 모델 선택·카메라 위치·촬영 조건부터 확인합니다. 기종별 실제 학습 범위와 품질 판정 미지원은 [모델 통합 안내](PHONE_PACKAGE_MERGE.md)를 따릅니다.

## 중지·오류

- **벨트 정지**, 검사 중지, 연결 해제, 통신·분석·저장 실패 시 자동 재구동하지 않습니다.
- 정지 후 검사·저장 중에는 수동 구동을 막습니다. 이동 중 도착 검출용 프레임 분석은 수동 구동을 막지 않습니다.
- 자동 재구동 체크를 해제하면 이전처럼 **검사 완료·해제 → 벨트 구동**으로 진행할 수 있습니다.
- 저장 응답이 끊긴 경우 이미 저장됐을 수 있으므로 이력을 확인한 뒤 수동 재시도합니다.

## 소리만 나고 회전하지 않는 증상

사진에서 확인된 RUNNING 응답은 펄스 출력 상태를 뜻합니다. 실제 회전·모터 온도 센서는 연결되어 있지 않습니다.

사용자가 단독으로 정상 동작을 확인한 코드는 **PUL 5번 / DIR 6번 / DIR LOW / 반주기 80µs**였습니다. 프로그램의 기존 2/3번 핀이 실제 정상 코드와 달랐음을 확인하여 5/6번과 80µs로 맞췄습니다. 앞서 추가했던 저속 램프는 제거했습니다. 이 출력은 유지하고 RUN/STOP, 통신 중단 정지와 카메라 자동 검사를 연결합니다. V3 이전 펌웨어는 구동 전에 거부하므로 사용자 앱 재실행과 보드 재업로드가 필요합니다.

실제 벨트 회전은 이번 소프트웨어 검증에서 직접 확인하지 않았습니다. 소음·과열이 지속되면 정지하고 전원을 끈 뒤 드라이버·전원·배선을 확인합니다.

## 확인한 범위

모의 카메라·벨트·서버와 실제 ONNX 모델로 이동 중 구동 허용, 정지 후 자동 재구동, 같은 제품 중복 방지, 수동 정지 취소와 실패 시 정지 등 51개 검증을 통과했습니다. 펌웨어 PC 모의 검증 17개를 통과했고 Mega 2560용 컴파일도 성공했습니다(Flash 3154 bytes, RAM 363 bytes). 실제 보드 업로드·모터 구동은 수행하지 않았습니다.
