# 휴대폰 학습 자료·모델 통합 안내

이 문서는 이전 6클래스 모델 통합 기록이다. 2026-10-19 기본 모델을 휴대폰 전체 외곽 단일 클래스 모델로 실제 재학습해 적용했다. 현재 파일·한계·백업은 [전체 외곽 재학습 적용 안내](PHONE_FULL_BODY_TRAINING_20261019.md)를 참고한다.

이후 선택한 PUL/DIR 제어를 연결했습니다. 최신 벨트 동작과 업로드 순서는 [컨베이어 통합 안내](PUL_DIR_CONTROL_INTEGRATION.md)를 참고하세요. 아래 모델·학습 자료는 유지합니다.

적용 파일: `새 폴더 (3).zip`, `models.zip`

## 적용 내용

- 기본 모델: `04_Vision/models/best.onnx`, 새 폴더의 6클래스 모델. 동일 모델과 체크포인트를 최상위 `models/best.onnx`, `models/best.pt`에도 반영했습니다.
- C# 검출기: 기존 1·3클래스와 새 6클래스 출력 지원, 기종 이름·신뢰도 표시, 새 기종도 휴대폰 검출 시 정지 명령에 연결했습니다.
- 사용자 화면: **YOLO 모델 선택** 버튼 추가. 검사 중에는 교체할 수 없고, 잘못된 파일을 선택하면 기존 모델을 유지합니다.
- 서버: 품질 판정 미지원 상태를 강제하면서 기종 이름을 포함한 검출 사유를 보존합니다. 관리자 이력에서도 해당 사유를 볼 수 있습니다.
- 모델과 각 모델의 `model_info.json`은 빌드·게시 시 실행 폴더로 항상 복사됩니다.

| 선택 가능한 모델 | 사용자 앱 실행 폴더 기준 경로 |
|---|---|
| 기본 기종 모델 | `Models/best.onnx` |
| `models.zip`의 기존 클래스 모델 | `Models/alternatives/01_기존_3클래스/best.onnx` |
| 이전 공유용 휴대폰 위치 모델 | `Models/alternatives/05_이전_휴대폰위치검출/best.onnx` |

서로 다른 학습 가중치는 각각 보관합니다. 동시에 여러 모델을 실행하거나 가중치를 합치지는 않습니다. 모델 선택은 현재 앱 실행 중에 적용됩니다.

## 사진·라벨·학습 자료

추가 자료 원본은 `imports/phone-merge-20261017-121058/labeled-project`, 추가 모델 전체는 같은 폴더의 `additional-model`에 보관했습니다. 학습 결과 이미지·CSV·체크포인트를 보존했습니다. 이전 PC를 가리키던 `dataset/data.yaml` 경로는 현재 폴더로 수정하고 원문은 `data.original.yaml`로 보관했습니다.

추가 사진 4장은 기존 프로젝트에도 동일한 사진이 있었습니다. 최상위 `images`에 같은 파일을 다시 넣지 않고, 기존 파일 이름을 유지하면서 `labels` 4개를 더 구체적인 기종 라벨로 반영했습니다. 클래스 번호 0~2는 유지하고 3~5를 추가했습니다. 원래 파일과 변경 내역은 백업 및 `imports/phone-merge-20261017-121058/merge_manifest.json`에 있습니다.

최상위 `dataset`은 기존 자료를 포함해 내용이 서로 다른 사진 7장으로 구성했습니다(학습 6장·검증 1장). 기존 중복 사진 2장의 박스가 약간 달라 대표 파일 하나를 사용했고, 원본 두 파일·라벨은 그대로 보관했습니다. 학습·검증에 동일 사진이 중복되지 않는지 확인했습니다. **통합 데이터로 재학습하지는 않았습니다.** 현재 기본 모델은 제공된 4장으로 학습된 모델입니다.

학습 도구에서 기존 프로젝트를 닫고 이 솔루션의 최상위 폴더를 **프로젝트 열기**로 다시 선택하면 확장된 클래스와 라벨을 볼 수 있습니다. 기존 `target_iphone` 라벨과 기종별 라벨은 의미가 다르므로 다음 재학습 전에 라벨 기준을 검토하세요. 학습 도구가 데이터셋을 다시 만들면 원본 중복 사진이 포함될 수 있으니 중복 파일도 정리하고 진행하세요.

## 확인된 범위와 한계

새 모델의 실제 제공 라벨은 `iphone_16` 2개, `iphone_15_pro` 2개입니다. `iphone_15`, `other_phone`, `crack`은 제공된 새 라벨에 없습니다. 클래스 이름이 있다는 이유만으로 이 항목의 검출 성능이나 깨짐 검사 기능을 보장하지 않습니다.

기종 검출을 정상/불량 판정과 분리했습니다. 모델별 `model_info.json`의 `classificationAvailable`을 false로 설정하여 판정 불가와 실제 신뢰도를 저장하고, 정상·불량 수치는 늘리지 않습니다. 형태·색상 점수는 미측정으로 표시합니다. 다음 단계에서는 정상 허용 기종을 정하고, 각 기종·불량·빈 벨트 사진을 확보해 따로 검증해야 합니다.

기본 신뢰도 50%에서 새 모델은 제공 사진 4장 중 3장에서 박스를 반환했습니다. 1장은 최고 신뢰도 약 43.9%로 기준 미달이었습니다. 이 수치는 제공된 소수 사진의 확인 결과이며 실제 환경 정확도를 나타내지 않습니다. 실제 컨베이어 조명·배경·거리에서 추가 확인이 필요합니다.

제공된 기종 라벨은 휴대폰 전체 외곽이 아니라 후면 카메라 부근을 둘러싼 박스입니다. 현재 박스와 도착 감지는 그 영역을 기준으로 합니다. 휴대폰 전체 외곽이 검출되어야 한다면 라벨을 수정하고 다시 학습해야 합니다.

## 실행 순서

1. 실행 중인 프로젝트 앱을 닫습니다.
2. `ProductionLineSystem.sln`을 Visual Studio에서 열고 솔루션을 다시 빌드합니다.
3. 서버 → 사용자 앱 순서로 실행합니다. 관리자 앱은 필요할 때 실행합니다.
4. 카메라 연결 → YOLO 모델 확인 → 검사 시작.
5. 다른 모델은 검사 중지 → YOLO 모델 선택 → `Models/alternatives`에서 선택 → 검사 시작.

아두이노 펌웨어와 속도 설정은 이번 통합에서 변경하지 않았습니다. 실제 모터 구동은 실행하지 않고 정지 명령을 모의 장치로 검증합니다.
