# C#에서 Mega 2560 업로드와 컨베이어 제어

## 처음 사용할 때

1. 기존 서버를 실행합니다. 서버 주소는 기존 PRODUCTIONLINE_SERVER_URL 설정을 사용하며 포트는 5050입니다.
2. 폴더의 `컨베이어_통합실행.cmd`를 더블클릭하고 사용자 계정으로 로그인합니다.
3. 실시간 검사 탭의 **아두이노 설정·업로드**를 누릅니다.
4. Mega 2560을 USB로 이 사용자 PC에 연결하고 해당 COM 포트를 선택합니다. 자동 식별된 Mega가 한 대면 자동 선택하며, 일반 COM1은 아두이노로 가정하지 않습니다.
5. **업로드·연결**을 누릅니다. 필요한 개발 도구 준비 → 현재 컨베이어 코드 컴파일 → 보드 업로드 및 검증 → 정지 상태 연결을 진행합니다. 보드의 기존 코드를 이 앱의 코드로 덮어쓰는 버튼입니다.
6. **카메라 연결 → 검사 시작 → 벨트 구동**으로 운영합니다.

Arduino IDE와 Visual Micro 설치는 필요하지 않습니다. 업로드 코드가 달라지지 않으면 다음부터는 설정 창을 열지 않고 **COM 선택 → 벨트 연결**을 사용합니다. 마지막으로 연결한 포트를 이 PC에 기억합니다.

## 설정 창 버튼

| 버튼 | 동작 |
|---|---|
| 개발 도구 준비 | 공식 AVR 컴파일러를 앱 전용 폴더에 준비. 보드에 코드를 쓰지 않음 |
| 컴파일만 확인 | Mega 2560용 펌웨어를 컴파일. USB 보드가 없어도 실행 가능하며 업로드하지 않음 |
| 업로드·연결 | 현재 코드를 다시 컴파일하여 선택한 COM 포트로 업로드, 이후 메인 화면에서 새 펌웨어 확인 및 STOP 응답 확인 |
| 작업 중단 | 해당 CLI 작업과 자식 프로세스를 중단. 업로드 도중 중단했다면 다시 업로드 필요 |
| 포트 확인 | 현재 COM 포트와 자동 식별된 보드 정보를 갱신 |

## 운영 흐름

휴대폰 검출 → STOP 응답 확인 → 정지 대기(기본 500ms) → 새 영상으로 재검사 → 기존 서버 저장 → 정지 유지입니다. **검사 후 자동 재구동**을 체크하면 저장 후 자동 이동합니다. 체크를 해제한 수동 모드에서는 결과 확인 후 **검사 완료·해제 → 벨트 구동**을 누릅니다. 업로드 성공이나 포트 연결만으로 모터를 켜지 않습니다. 사용자가 정상 동작을 확인한 PUL=5 / DIR=6 / DIR=LOW / 반주기 80µs를 사용합니다. V3 이전 핀 설정 펌웨어는 연결 시 거부합니다. 실제 장비에 맞는 속도·전류 검증은 필요합니다. 물리적 정지는 피드백 센서로 측정하지 않으므로 대기 시간은 실제 장비로 확인합니다.

검사 처리나 명령이 진행 중이면 끝난 뒤 설정 창을 엽니다. 설정 창을 열 때 연속 검사를 중지하고 연결된 벨트의 정지 응답을 확인한 뒤 시리얼 연결을 해제합니다. 정지 응답 확인에 실패하면 그 시도에서는 업로드 창을 열지 않습니다. 사용자가 문제를 확인한 후 다시 시도할 수 있습니다.

## 파일·도구 위치

- `02_UserApp/ProductionLine.UserApp/ArduinoFirmwareTools.cs`: 공식 CLI 실행, 전용 설정, 컴파일·업로드·취소 처리.
- `ArduinoSetupForm.cs`: Mega 2560 설정 창 및 마지막 COM 포트 기억.
- `ArduinoSetupControls.cs`: 메인 화면과 업로드 창 연결, 업로드 후 정지 상태 재연결.
- `tools/arduino-cli/`: 공식 Arduino CLI 1.5.1 Windows x64, LICENSE.txt, 출처·체크섬 provenance.json.
- `hardware/ConveyorYoloControl/ConveyorYoloControl.ino`: 컴파일할 원본 아두이노 코드. 사용자 앱 빌드·게시 때 Hardware 폴더로 함께 복사.
- 사용자 앱의 csproj가 CLI, 라이선스, 펌웨어를 실행 폴더에 복사합니다. 공유할 때 tools/arduino-cli와 hardware도 포함해야 합니다.
- 최초 AVR 코어 준비 위치: `%LOCALAPPDATA%/ProductionLine/ArduinoTools`. Arduino IDE의 Arduino15 폴더와 기존 프로젝트는 수정하지 않습니다.
- 보드: `arduino:avr:mega:cpu=atmega2560`, AVR 코어 1.8.8.

CLI 배포 파일은 Arduino 공식 체크섬으로 확인했습니다. 포함된 GPL-3.0 라이선스와 공식 소스 링크를 함께 유지하세요. [공식 소스·릴리스](https://github.com/arduino/arduino-cli/releases/tag/v1.5.1), [컴파일 명령](https://arduino.github.io/arduino-cli/1.5/commands/arduino-cli_compile/), [업로드 명령](https://arduino.github.io/arduino-cli/1.5/commands/arduino-cli_upload/).

## 오류가 나면

- 포트 없음: USB 케이블·장치 관리자·Mega 포트를 확인합니다. USB 변환칩 보드가 자동 식별되지 않으면 COM을 직접 선택합니다.
- 포트 사용 중: Arduino IDE 시리얼 모니터나 다른 COM 프로그램을 닫고 다시 시도합니다.
- 도구 준비 실패: 인터넷 연결과 설정 창의 로그를 확인한 뒤 다시 준비합니다.
- 업로드 실패/중단: 성공으로 표시하거나 연결하지 않습니다. 원인 해결 후 다시 업로드합니다.
- 업로드 성공 후 연결 실패: 코드는 업로드됐지만 시리얼 응답은 확인되지 않은 상태입니다. 포트 갱신 후 벨트 연결을 누릅니다.

새 서버/API는 추가하지 않았고 ProductionLineApiClient.cs, Contracts.cs 형식은 그대로입니다. Arduino USB는 YOLO와 사용자 앱을 실행하는 PC에 연결합니다.

## 현재 솔루션 적용 및 검증

이 업로드 기능은 사용자가 선택한 바탕화면의 컨베이어 제어 폴더에서 현재 솔루션으로 가져왔습니다. 최근 추가한 6클래스 모델·모델 선택·신뢰도 저장 API는 유지했습니다. 현재 제어·실행 순서는 `hardware/README.md`를 따릅니다.

현재 사용자 앱과 검증 프로젝트 빌드는 경고 0·오류 0입니다. PC의 C++ 펌웨어 모의 검증 15개, 모의 업로드·프로세스 검증 16개, 설정 창 UI 12개, 실제 ONNX와 모의 컨베이어 연동 38개로 총 81개를 통과했습니다. 실제 Mega용 AVR 재컴파일·보드 업로드·모터 구동은 이번 통합 작업에서 수행하지 않았습니다. 최초 도구 준비와 실제 보드 연결 후 확인이 필요합니다.

재현: Verification.dll에 `--arduino-tools`, `--arduino-dialog`, `--continuous-yolo 사진경로` 인수를 사용합니다. 업로드 도구 검증의 업로드 명령은 모의 실행기를 사용합니다. 설정 창 UI 검증은 분리된 임시 설정을 사용합니다.
