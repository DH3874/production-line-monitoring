# 생산라인 휴대폰 검사·운영 지원 시스템

현재 구현 기준 · 2026-10-19 · 5명 공동 개발

## 1. 프로젝트 목적

컨베이어로 이동하는 휴대폰을 카메라와 YOLO로 검출하고, 관리자와 작업자가 검사 기록과 라인 문제를 함께 관리하는 C# 기반 시스템이다. 문제 발생 시 작업자는 매뉴얼 기반 상담 AI로 점검 방법을 안내받고 관리자에게 문의할 수 있다.

**기본 운영 원칙: 휴대폰을 인식해도 벨트는 멈추지 않는다. 검출·기록과 벨트 구동을 별도로 제어한다.**

## 2. 전체 흐름

서버 실행 → 사용자 로그인 → 카메라·벨트 연결 → 모델 확인 → 검사 시작 → 벨트 구동 → 이동 중 연속 검출·화면 표시 → 제품별 기록 저장 → 다음 제품 검출

문제 발생 → 사용자 문제 등록·확인 → AI 상담 또는 관리자 문의 → 조치 내용 기록 → 완료 요청 → 관리자 검토·종결 또는 반려

## 4. 검출과 벨트 동작 기준

| 항목 | 현재 기준 |
|---|---|
| 기본 검사 방식 | 이동 중 연속 검출, 인식에 따른 STOP 명령 없음 |
| 검출 주기 | 목표 0.1초. PC 성능과 모델 추론 시간에 따라 실제 간격은 길어질 수 있음 |
| 검출 신뢰도 | 기본 50% 이상 |
| 기록·결과 표시 | 새 휴대폰을 인식했을 때 제품 번호·기종·신뢰도·시각과 당시 사진을 한 번 표시하고 기록. 실시간 영상은 계속 갱신하되, 마지막 인식 결과는 다음 제품까지 유지 |
| 다음 제품 구분 | 검출되지 않는 상태를 마지막 검출 후 250ms 이상 지나 확인하면 다음 제품 기록 가능 |
| 검사 중지 | 영상 분석·기록을 중지. 기본 연속 모드에서는 벨트 구동 상태를 바꾸지 않음 |
| 연결 관리 | 벨트 연결 해제·업로드 준비·종료·통신 중단에 필요한 기존 장치 연결 처리는 유지 |
| 정지 연동 | 검출 정지 체크박스·벨트 정지 버튼·정지 후 재검사·재구동 기능 제거 |

실시간 카메라와 마지막 인식 제품 사진을 함께 표시한다. 검사 이력의 행을 선택하면 당시 저장한 인식 사진을 별도로 조회한다. 사진이 없는 이전 기록은 ‘저장된 인식 사진 없음’으로 표시한다. 검사 중지는 분석·기록만 중지하며 벨트를 제어하지 않는다.

화면의 인식 제품 번호는 연결·모델 세션 내 표시 순번이며 서버의 검사 ID와는 별개다. 카메라 새 연결, 모델 변경 또는 라인 변경 시 사진과 결과를 초기화한다.

제품 간 빈 구간이 있어야 개수를 구분할 수 있다. 현재 방식은 다중 제품 추적 기능이 아니므로 여러 휴대폰이 동시에 겹치거나 빈 구간 없이 연속 통과하면 개별 계수가 보장되지 않는다. 검사 중지 후 재시작하면 화면에 남은 같은 제품도 새 기록이 될 수 있다.

## 5. 실제 검출 범위

2026-10-19 사용자 제공 모델을 기본 모델로 적용했다. 클래스는 `target_iphone`, `other_phone`, `crack`, `crack_phone`이며 448×448 ONNX를 사용한다. 적용 전 단일 `phone` 전체 외곽 모델은 대체 모델로 보존한다. 사용자 제공 모델에는 여섯 기종 분류·색상 4종·cm 치수 기능이 없다. [영상처리 안내](../04_Vision/README.md)를 참고한다.

**현재 통합 모델은 휴대폰·기종 검출을 확인하는 단계다. 정상/불량 품질 판정은 ‘판정 불가’로 기록하고, 실제 검출 신뢰도를 별도로 저장한다.** 깨짐 판정, 허용 기종 외 제품의 불량 처리, 형태·색상 검사 기준은 추가 데이터와 검증 후 적용한다. 기존 정상/불량 검사 시뮬레이션은 실제 카메라 검사와 구분한다.

상담 AI는 라인 문제의 원인·점검 순서·대응 방법을 안내하며, 벨트를 직접 제어하지 않는다. 제품 검출은 별도의 YOLO 영상처리 모듈이 담당한다.

## 6. 기술 구조

관리자 C# WinForms / 사용자 C# WinForms ↔ 유선 이더넷 HTTP·JSON ↔ C# ASP.NET Core 서버 ↔ JSON 저장소

사용자 앱 ↔ OpenCvSharp + ONNX Runtime ↔ 카메라·YOLO 모델

사용자 앱 ↔ USB 시리얼 9600 baud ↔ Arduino Mega ↔ PUL/DIR 모터드라이버

서버 ↔ 매뉴얼 검색·상담 로직 / 설정된 외부 AI API

PC 프로그램은 C#/.NET 8이며, 모델 학습은 Python Ultralytics, 보드 펌웨어는 Arduino C++를 사용한다. 이더넷은 PC 간 통신이고 보드 연결은 USB 시리얼이다. 현재 영구 저장은 SQL DB가 아닌 JSON 파일 기반이다.

벨트 출력은 정상 동작한 단독 코드를 기준으로 PUL 5번, DIR 6번 LOW, 펄스 반주기 80µs이다. PC 명령으로 구동·정지하며 보드 연결만으로 자동 출발하지 않는다. 펌웨어 식별자는 `PL_CONVEYOR_PUL_DIR_V3`이다.

## 8. 발표 시연

1. 관리자 로그인 후 전체 라인과 등록 사용자를 확인한다.
2. 사용자 로그인 후 대표 라인에서 카메라·벨트를 연결한다.
3. 검사 시작과 벨트 구동을 누르고 휴대폰을 통과시킨다.
4. 벨트가 계속 이동하는 동안 검출 박스·기종·신뢰도가 표시되고 제품 기록이 저장되는 모습을 보여준다.
5. 문제를 등록하고 AI 상담·관리자 문의·조치 기록·완료 요청을 시연한다.
6. 관리자가 검토·종결하고 검사 이력과 통계를 확인한다.

장비를 직접 구동하지 않은 소프트웨어 검증과 현장 검증은 구분한다. 모델 정확도·제품 계수·실제 모터 동작은 최종 장비의 조명·속도·제품 간격에서 별도 확인한다.



사진은 서버 `data/inspection-images`에 검사 ID로 저장하고 권한이 있는 사용자만 조회한다. 기존 검사 저장 상한 500건·화면 조회 100건을 유지하며, 저장 상한으로 제거되는 기록의 사진도 정리한다. 사진 저장을 사용하려면 서버와 사용자 앱을 함께 최신 버전으로 실행한다.
