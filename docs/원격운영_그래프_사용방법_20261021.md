# 작업자 환경 그래프 · 관리자 원격 운영

현재 프로젝트 폴더의 소스에 적용했다. 첨부한 원본 ZIP은 그대로 두었다.
실행 파일은 `output/생산라인_원격운영_20261021`에 있다.

## 실행 순서

1. 이전 서버·관리자·작업자 프로그램을 종료한다.
2. 실행 폴더의 **서버_실행.cmd**를 실행한다. 서버 창은 켜 둔다.
3. **작업자_실행.cmd**를 실행하고 작업자 계정으로 로그인한다.
4. 카메라와 아두이노 COM을 연결한다. 온습도·가스 상태가 들어오면 작업자 실시간 검사 화면 오른쪽 그래프가 갱신된다. 아래 장비 버튼이 안 보이면 화면을 아래로 스크롤한다.
5. **관리자_실행.cmd**로 로그인하고 상단의 **작업자 원격 운영 · 그래프**를 누른다. 대표 라인의 상세 화면에서도 열 수 있다.

기존 계정을 사용한다. 초기 테스트 계정은 작업자 `worker1 / worker123!`, 관리자 `admin / admin123!`이다.
작업자 앱은 실행·로그인된 상태여야 원격 명령을 받을 수 있다. 한 라인은 한 작업자 앱 연결이 담당한다.

## 관리자 원격 운영 화면

| 탭 | 확인·제어 기능 |
|---|---|
| 영상 · 원격 제어 | 작업자 검사 영상, 마지막 인식 제품 사진, 현재 검사·장비 상태 |
| 온습도 · 가스 그래프 | 작업자와 같은 실측 센서 그래프, 현재 온도·습도·가스·긴급 정지 상태 |
| 검사 기록 · 제품 사진 | 최근 100개 검사 기록 조회, 기록을 선택하면 해당 제품 사진 표시 |
| 원격 명령 실행 이력 | 전달 대기 / 실행 중 / 완료 / 실패 / 기한 만료 / 결과 미확인 구분 |

원격 제어 항목:

- 카메라 번호 선택, 연결·해제, 검사 시작·중지.
- COM 포트 조회·선택, 벨트 연결·해제, 구동·정지.
- D7 조명 켜기·끄기.
- 불량 자동 분류 켜기·끄기, 검사→분류 이동 시간, 55° 유지 시간 설정.
- 작업자 PC에 있는 모델 목록에서 개별 모델 또는 전체 학습 모델 선택. 검사 중에는 모델을 바꾸지 않는다.
- 작업자 화면을 실시간 검사 / 검사 이력 / 문제·조치 / AI 상담 / 관리자 상담 / 단체 채팅으로 이동.
- 검사·벨트 동시 정지. 원격 모델 준비 중에도 우선 수신한다.
- 긴급 정지 잠금 해제 요청. **현장의 물리 NC 버튼이 해제된 상태에서만 펌웨어가 허용하며, 벨트를 자동 재출발시키지 않는다.**

관리자 화면에 표시되는 명령 전송 성공은 장비 동작 완료와 다르다. 명령 실행 이력에서 작업자와 장비의 실제 응답을 확인한다. 응답이 불확실한 구동 명령은 자동 재전송하지 않는다. 연결이 끊긴 상태에서는 제어 버튼이 비활성화되며, 재연결 후 과거 대기 명령을 자동 실행하지 않는다.

원격 운영은 이 프로그램의 기능을 제어한다. 초기 아두이노 펌웨어 설치는 작업자 PC의 기존 **아두이노 설정·업로드** 기능을 사용한다. 관리자 자신의 기존 사용자 관리·문제 처리·상담·단체 채팅 기능도 그대로 사용할 수 있다.

## 그래프가 의미하는 값

| 그래프 | 입력 | 표시 |
|---|---|---|
| 온도 | D30 DHT11 | ℃, 약 2초 단위 실측 |
| 습도 | D30 DHT11 | 상대습도 % |
| 가스 | MQ9 AO → A0 | 0~1023 아날로그 원시 입력값 |

가스 센서는 AO → A0로 변경했다. 0~1023 원시 입력값을 그리며 ppm 농도나 감지 판정으로 환산하지 않는다. 첫 60초에도 입력값은 표시하고 초기 예열 중임을 알린다. 수신이 끊기면 현재 값은 미확인으로 표시한다. 이전 V4/V5 보드를 사용하는 동안에는 기존 DO 감지(0/1) 표시가 유지된다.

최근 10분의 센서 흐름을 서버 메모리에 보관하고 두 앱에 함께 표시한다. 서버 재시작 시 이 그래프 이력과 원격 명령 목록은 초기화된다. 기존 SQLite 검사 기록·문제·사용자 데이터와 검사 사진은 별도이며 유지한다. 실시간 영상은 네트워크 미리보기로 약 1초마다 갱신하고 원본 프레임 수신 시각을 표시한다.

## 다른 PC에서 이더넷으로 사용

1. 서버 PC에서 서버를 실행한다. 관리자·작업자 PC가 같은 LAN에서 서버 PC에 접근할 수 있어야 한다.
2. 관리자·작업자 실행 폴더의 **서버주소.txt**를 메모장으로 열어 첫 줄을 `http://서버PC_IP:5050`으로 바꾼다. 예: `http://192.168.0.10:5050`.
3. 관리자·작업자 앱을 다시 실행해 로그인한다. 같은 PC에서 모두 실행하면 기본 `http://127.0.0.1:5050`을 사용한다.
4. 연결이 안 되면 서버 창, 서버 PC의 IP, Windows 방화벽의 해당 LAN 통신 허용 여부를 확인한다. 카메라와 USB 아두이노는 작업자 PC에 연결한다.

환경 변수 `PRODUCTIONLINE_SERVER_URL`이 이미 설정되어 있으면 그 주소가 파일보다 우선한다.

## 기존 데이터·하드웨어

- 프로젝트 폴더 안에서 제공된 서버 실행 파일을 쓰면 기존 `03_Server/ProductionLine.Server`의 DB·사진 폴더를 그대로 사용한다. 데이터 파일을 덮어쓰거나 새 DB로 바꾸지 않는다.
- 실행 폴더만 다른 위치로 옮겨 독립 서버로 실행하면 그 위치의 서버 폴더에 새 DB가 생긴다. 기존 기록이 필요하면 원래 프로젝트 안에서 서버를 실행한다.
- 기존 YOLO 모델·검출 기준·AI 상담·검사 기록·계정 관리 기능은 유지했다.
- 가스 입력은 AO → A0로 변경하고 나머지 핀은 유지한다. 이동 대기와 55° 유지는 각각 최대 60,000ms까지 설정할 수 있다. 최신 V7를 업로드하면 시간 확장·모든 제품 인식 후 가속·A0 측정을 함께 사용할 수 있다. V4/V5는 각 버전에서 지원하는 기존 기능 범위에서 계속 연결할 수 있다.
- 실제 긴급 정지는 현장 NC 접점과 모터 구동 전원을 차단하는 회로로 구성한다. 네트워크 정지 버튼은 물리 긴급 정지 장치를 대체하지 않는다.

## 검증

관리자·작업자·서버 빌드 및 별도 테스트 서버/테스트 DB/가짜 장비로 원격 명령, 인증·권한, 중복 방지, 우선 정지, 연결 만료, 영상 전달, 검사별 사진 일치, 그래프 화면을 확인했다. 실제 카메라·모터를 구동하지 않았으므로 현장 LAN과 장비 응답은 연결 후 확인한다.

## 추가 변경 · 가스 A0와 모든 제품 인식 후 가속
새 작업자 앱에서 아두이노 설정·업로드 → COM3 → 업로드·연결을 한 번 실행한다. 보드 코드가 V7로 바뀐다. 다른 작업자 앱과 IDE 시리얼 모니터는 닫아 COM3 점유를 해제한다.
정상·불량 모두 새 제품 인식 후 설정한 시간(0.5~60초, 기본 3초) 동안 2배 속도로 구동한 뒤 기본 속도로 복귀한다. 기본속도 이동(ms)에는 기존 100µs 속도에서 측정한 검사→분류 시간을 입력한다. 가속에 따른 분류 도착 시점은 펄스 속도 이력으로 보정하고 55° 유지 시간은 실제 초 단위로 유지한다. 실물 이동 오차는 현장에서 확인한다.

작업자 화면에서 가속 유지 시간(초)을 직접 변경하거나, 관리자 원격 운영 화면에서 시간을 입력하고 가속 시간 적용을 누른다. 다음 제품 인식부터 적용하며 이미 진행 중인 가속 시간을 소급 변경하지 않는다. 앱 재실행 시 기본값 3초로 시작한다. 기존 V6 보드 연결 시 기존 1.25배/3초로 동작하므로 새 기능은 V7 업로드 후 사용한다.

## 관리자 대시보드 시뮬레이션
상단은 정지/재생 버튼 하나로 제어한다. 창을 열면 네 카드의 시연 애니메이션이 재생된다. 한 번 누르면 모두 정지하고 다시 누르면 멈춘 위치에서 재생한다. 화면 밖 라인도 계속 진행한다. 자동 데이터 갱신이 일시정지를 해제하지 않는다.
라인2·3·4는 각각 정상12/불량1, 정상18/불량2/판정불가1, 정상9/불량0의 예시 데이터로 시작한다. 재생 중 가상 수량이 조금씩 증가하고 정지하면 가상 생산 시간도 멈춘다. 이 값은 대시보드 시연용이며 DB와 실제 검사 통계에 저장하지 않는다.
실제 라인1의 숫자·센서 상태는 서버에서 받은 실제 정보를 유지하고, 카드 그림에는 실제 벨트와 별개인 시뮬레이션이라고 표시한다. 아두이노 연결 여부와 관계없이 시연 그림은 재생할 수 있다.
완료 요청 확인 버튼은 관리자 메뉴에 다시 제공한다. 대시보드의 완료 요청 수치와 카드의 완료 요청 표시는 표시하지 않는다. 검사 기록·사진·자동 갱신·기존 문제 데이터는 유지한다.
시뮬레이션 버튼은 실제 장비 명령을 보내지 않는다. 실제 구동/정지와 D12 잠금 해제는 작업자 앱 또는 관리자 작업자 원격 운영 화면에서 조작한다.
적용은 관리자 앱만 종료 후 재실행한다. 서버 재시작이나 Arduino 업로드는 필요 없다.
## 가상 라인 검사 결과·이력 예시
라인2·3·4에 서버 기록이 없으면 관리자 검사 결과와 검사 이력 화면에 각5건의 가상 예시를 표시한다. 각 라인은 정상3건·불량1건·판정불가1건이며 가상 전체15건이다. 자동 갱신 중 ID와 시각은 고정되어 중복되지 않는다. [가상 예시]로 표시하며 실제 DB 검사 기록이나 실제 통계에 저장/합산하지 않는다. 예시에는 촬영 사진이 없으므로 사진 없음으로 표시한다. 서버에 이미 해당 라인의 기록이 있으면 기존 기록을 우선 표시한다.

## 관리자 라인 배치
네 라인은 2열×2행으로 표시한다. 왼쪽 위 대표 라인1, 오른쪽 위 가상 라인2, 왼쪽 아래 가상 라인3, 오른쪽 아래 가상 라인4이다. 창 크기에 맞춰 카드와 시뮬레이션 그림을 조정해 라인 가로 스크롤을 없앴다. 실제 상세 센서 정보는 상세 보기와 카드 하단에 마우스를 올렸을 때의 안내로 확인한다. 정지/재생, 완료 요청 확인, 가상 검사 기록은 유지한다. 관리자 앱만 재실행하면 적용한다.
