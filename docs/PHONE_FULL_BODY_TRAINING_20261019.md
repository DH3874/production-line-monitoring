# 휴대폰 전체 외곽 재학습 적용 (2026-10-19)

> 후속 변경: 2026-10-19 11:32에 사용자 제공 4클래스 모델을 기본 `best.onnx`/`best.pt`로 적용했다. 이 문서의 단일 `phone` 모델은 `04_Vision/models/alternatives/03_휴대폰전체검출_적용전백업`에 보존된 이전 모델에 관한 기록이다. 현재 기본 모델 정보는 [영상처리 안내](../04_Vision/README.md)를 참고한다.

## 현재 적용 모델

`models/best.pt`, `models/best.onnx`, `04_Vision/models/best.pt`, `04_Vision/models/best.onnx`를 실제 재학습 결과로 교체했다. 기본 ONNX는 휴대폰 본체 전체를 검출하는 단일 클래스 `phone` 모델이다. 기종 6개를 구분하거나 색상·파손·cm 치수를 판정하는 모델은 아니다.

앱 재실행 후 기본 모델을 사용하거나 **검사 중지 → YOLO 모델 선택 → `04_Vision/models/best.onnx` → 검사 시작**을 선택한다. 이전 게시 폴더의 실행 파일을 사용하는 경우에도 새 모델을 직접 선택할 수 있다. px 표시와 가장자리 기록 대기 기능은 다시 빌드한 사용자 앱에 적용된다.

열려 있는 학습 도구는 이전 클래스 목록을 메모리에 가지고 있을 수 있으므로 프로젝트를 닫았다 다시 연 뒤 라벨링한다. 최상위 프로젝트의 현재 클래스는 `phone` 하나다.

## 학습 자료와 방법

- 서로 다른 실제 원본 7장을 모두 전체 휴대폰 외곽 박스로 다시 표시했다.
- 학습 5장·검증 2장으로 구성했다. 같은 촬영 환경이므로 독립적 성능 검증이 아니다.
- 1차 기종 포함 모델을 100회 학습했지만 신뢰도 50% 기준에서 부족해 배포하지 않았다.
- 그 체크포인트의 전체 외곽 특징을 이어 받아 `phone` 단일 클래스로 추가 80회 학습했다.
- 크기 변화 scale 0.5, multi_scale 0.1, 이동 0.15, 회전 20도, 밝기·색감 보정을 적용했다.
- 증강 사진을 새 실제 사진으로 계산하지 않았다. 실제 원본 수는 계속 7장이다.
- 최상위 `classes.txt`, `labels`, `dataset`도 새 모델의 단일 클래스 ID와 맞췄다. 예전 데이터셋은 `imports/full-phone-before-20261019/dataset`에 보존했다.

## 확인 결과

기본 신뢰도 50%에서 휴대폰 전체 정답 박스와 IoU 0.5 이상인 검출을 통과 기준으로 사용했다.

| 진단 자료 | 기존 카메라 영역 모델 | 새 전체 외곽 모델 |
|---|---:|---:|
| 기존 원본 7장 | 0/7 | 7/7 |
| 원본을 65% 크기로 줄인 진단 이미지 | 0/7 | 7/7 |
| 원본을 40% 크기로 줄인 진단 이미지 | 0/7 | 7/7 |
| 같은 세션 검증 사진 2장(위 7장에 포함) | 0/2 | 2/2 |

첨부 화면에서 잘라낸 실제 빈 벨트 영역은 새 모델에서 검출 0개였다. C# ONNX 실행에서도 7장 모두 전체 박스 검출이 확인됐고, 신뢰도는 약 69.2~85.5%, 전체 박스 IoU는 0.874~0.924였다.

사용자 앱·검증 프로젝트 빌드는 경고 0·오류 0으로 완료됐다. 전체 솔루션의 기본 출력 폴더 빌드는 실행 중인 서버 DLL과 학습 도구 EXE가 잠겨 복사 단계에서 실패했다. 실행 중인 앱은 종료하지 않았으며 사용자 앱의 새 모델과 C# 검증 결과에는 영향이 없다.

서버는 `output/full-phone-verification/server-build`의 별도 출력 폴더로 경고 0·오류 0 빌드에 성공했다. 기존 6클래스·추가 3클래스·이전 phone 모델을 보존한 뒤 실행한 기존 패키지 검사 27개도 통과했다. 사용자 앱 실행 폴더의 기본 ONNX SHA-256이 새 원본과 일치함을 확인했다.

이 결과는 새 사진에 대한 정확도나 모든 기종의 검출률을 의미하지 않는다. 크기 변화 진단도 기존 원본을 변형한 검사다. 특히 검정·퍼시픽 블루 등 현재 원본에 없는 외관과 다른 카메라 높이·조명·배경은 추가 실제 사진으로 확인해야 한다.

## 사용자 앱 변경

- 검출 박스와 인식 결과에 영상 좌표 기준 가로×세로(px)를 표시한다.
- 검출 박스가 화면 가장자리에 닿으면 기록을 기다린다. 진입 초기에 잘린 사진이 바로 마지막 인식 제품으로 고정되는 상황을 줄인다.
- 경계 검사는 박스 기반 조건이므로 전체 본체가 보인다는 절대적 보장은 아니다. 실제 이동 영상에서 확인해야 한다.
- 벨트 연속 이동과 품질 판정 미지원 정책을 유지한다.

## 요청한 색상 4종

검정·흰색·실버·퍼시픽 블루의 별도 분류 프로젝트를 `training/phone_colors`에 준비했다. 사용자가 실제 색상 사진이 아직 없다고 확인했으므로 색상 학습은 실행하지 않았고 색상 가중치도 생성하지 않았다.

`tools/train_phone_colors.py`는 실제 자료를 확인하고 4색 각각 학습 20장·검증 5장 이상이 있어야 실행한다. 실제 촬영은 색상당 학습 100장·검증 25장·최종 테스트 25장을 1차 목표로 권장한다. 흰색/실버의 실제 제품 색상 정답과 다른 촬영 세션 구분이 필요하다.

## 실제 크기와 기종 한계

px는 카메라 영상에서 차지하는 크기다. cm 치수를 얻으려면 같은 평면의 기준 길이와 카메라 보정이 필요하다. 현재 해당 자료가 없어 cm 숫자는 표시하지 않는다. 12 Pro와 12 Pro Max 등 기종 구분은 실제 기종별 촬영 자료가 추가로 필요하다.
